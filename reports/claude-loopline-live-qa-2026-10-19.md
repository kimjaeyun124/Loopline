## 요약

Claude를 모델 선택 및 Harness 경로에 연결해 동일한 Focus Ledger 과제를 실행했습니다. 그러나 두 실행 모두 Claude 계정의 세션 한도에 걸렸습니다. 단독 실행은 계획 단계에서 멈췄고, Loop 실행은 Claude를 첫 구현 모델로 시도한 뒤 저장된 우선순위에 따라 GPT-6.1 Sol로 자동 전환했습니다.

GPT 대체 경로가 만든 앱은 Loop 밖에서 실제 Chromium QA를 수행해 데스크톱과 모바일의 통합 테스트 16개 및 독립 브라우저 검사 36개, 총 52개를 모두 통과했습니다. 다만 Loop 자체는 마지막 통합 단계에서 제한된 실행 환경이 Chromium 자식 프로세스를 차단하는 `spawn EPERM`을 반복해 자동 완료 판정을 내리지 못했습니다. 따라서 이 실행은 **Claude 코드 품질 비교가 아니라 Claude 한도 초과 시 자동 대체와 검증 경계의 실측**입니다.

## 비교 조건

- 두 실행에 같은 기능 요구를 사용했습니다: 작업 추가·완료·실행 취소·삭제, 검색·필터, `localStorage` 저장 및 복원, 접근성, 1440×900과 390×844 반응형, 실행 안내와 자동 테스트.
- 브라우저 QA 계약은 각 화면 크기에서 18개 검사로 고정했습니다.
- Claude 단독 실행은 Planner·Judge를 포함해 전 역할에 Claude Sonnet 5를 배정했습니다.
- Claude 우선 Loop는 Planner GPT-5.6 Luna medium, Worker Claude Sonnet 5 high, Judge GPT-6.1 Sol high로 시작했습니다. Claude 한도 오류 후 Worker가 GPT-6.1 Sol high로 자동 전환됐습니다.
- 토큰은 모델 제공자가 반환한 실행별 사용량입니다. 달러 비용은 실행별 과금 자료가 없어 계산하지 않았습니다.

## 원인과 해석

1. **Claude 성능을 비교할 유효한 구현 결과가 없습니다.** 단독 Claude는 계획 도중 세션 한도 오류로 종료됐고, Loop에서도 Claude Worker 첫 호출이 같은 이유로 실패했습니다. 이를 코드 품질 저하나 모델 성능 실패로 해석하면 안 됩니다.
2. **모델 대체는 동작했습니다.** Loop는 Claude 실패 후 GPT-6.1 Sol로 전환하여 앱과 세 개의 부분 작업을 만들었습니다. 이는 한도 장애에 대한 복구 근거입니다.
3. **최종 자동 완료는 아직 불안정합니다.** Loop의 마지막 검증 명령 안에서 브라우저를 직접 실행하려다 샌드박스의 `spawn EPERM`에 막혔습니다. 실패한 통합 명령 뒤에 연결된 브라우저 QA도 실행되지 않았고, 같은 기준을 완화하지 않은 채 반복했습니다. 호스트에서 같은 프로젝트를 검사하면 Chromium 검증은 모두 통과했으므로 현재 근거는 앱 결함보다 Loop와 브라우저 실행 경계의 문제를 가리킵니다.
4. **Loop의 토큰·시간은 이번 조건에서 크게 증가했습니다.** GPT 대체 후 산출물 QA는 성공했지만 총 1.67M 토큰과 약 29분이 들었고 Harness는 완료 상태를 기록하지 못했습니다. 따라서 이번 결과에서 Loop가 더 효율적이라고 볼 수 없습니다.

## 결론 및 다음 개선 순서

- Claude가 실제로 호출 가능한 시간대에 같은 과제를 다시 실행해야 Claude 단독 품질과 Loop 내 Claude Worker 품질을 비교할 수 있습니다. 현재 결과로 Claude와 GPT의 코드 품질 순위를 매기지 않습니다.
- Loop에서는 샌드박스 안의 `verifyCommand`를 Node 기반 부분 테스트로 제한하고, 실제 Chromium 브라우저 QA는 이미 마련된 호스트 `BrowserQaBridge` 단계에서 실행하도록 검증 계약을 분리해야 합니다.
- `spawn EPERM` 같은 환경 오류는 앱 기능 결함과 별도 유형으로 기록하고, 독립 호스트 QA가 실제 통과했을 때 그 증거를 최종 판정에 전달하도록 해야 합니다. 통과 증거 없이 회차를 무제한 늘리지 않도록 같은 실패의 반복 횟수와 토큰 상한도 설정할 필요가 있습니다.
- 다음 공정 비교는 Claude 한도 복구 후 동일 프롬프트·QA 기준·최대 시간/토큰을 고정하고, 단독 Claude, Claude 우선 대체 Loop, GPT 단독을 각각 수행해야 합니다. 이때 완료율, QA 통과율, 사람의 개입 시간, 경과 시간, 모델별 토큰을 따로 집계합니다.
