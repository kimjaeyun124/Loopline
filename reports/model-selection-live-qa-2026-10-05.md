## 기능 근거 테스트

자동 테스트에서는 다음 조건을 검증했습니다.

- 완료 안정성을 토큰 효율·속도보다 먼저 고려합니다.
- 사용자가 설정한 우선순위는 비교 가능한 실측치가 충분한 항목에만 적용됩니다.
- 실측 정보가 없거나 누락된 값을 0으로 취급하지 않습니다.
- 모델 비교는 작업 유형, Loop 역할, Effort를 구분합니다.
- 모델 측정은 서로 다른 실행 3회 이상을 요구하고, 중지·중단 실행을 최종 완료 성능으로 계산하지 않습니다.
- 잔여 한도가 소진된 모델을 자동 후보에서 제외하고, 저장한 대체 순서를 유지합니다.
- 모델 검색, 설정 저장·복원, 우선순위 변경, Jev의 판정 전용 역할도 검증합니다.

## 제한 사항과 후속 권고

1. **모델별 승자를 확정할 만큼 표본이 충분하지 않습니다.** 실제 화면의 역할별 측정에는 표본 축적 중 상태가 표시됩니다. 같은 작업 유형·역할·Effort 조합으로 각 모델을 최소 3회 이상 실행한 뒤 비교해야 합니다.
2. **이번 QA에서 실시간 모델 호출을 하지 않았습니다.** 따라서 실제 선택 모델, 제공자별 응답 품질, 토큰 사용량, 실행 시간, 비용은 이번 결과로 주장하지 않습니다.
3. **제공자별 강점 정보의 밀도가 다릅니다.** Codex 모델은 간단한 강점 라벨이 보이지만, Gemini 후보는 화면에서 주로 모델 ID로 표시됩니다. 향후에는 제공자별 공식 메타데이터와 실제 실측 근거를 구분해 보여주는 편이 선택에 더 유용합니다.
4. 설정의 역할이 `자동`일 때 판정 모델이 후보를 고르고, 직접 지정한 역할은 고정됩니다. 실측 자동 배정을 확인하려면 실제 실행에서 자동 역할 설정을 사용해야 합니다.
