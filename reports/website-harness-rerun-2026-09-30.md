# Morrow 웹사이트 제작: 단독 Harness와 Loop 재실행 QA

작성일: 2026-09-30

## 요약

같은 팀 작업 관리 웹사이트 요구사항을 GPT-6 Luna Max 단독 Harness와 Loop Harness로 각각 실행했습니다. 두 산출물은 자체 테스트를 통과했고, 별도 브라우저에서 같은 작업 데이터로 추가·검색·완료·필터·새로고침 저장·삭제를 확인했습니다. 두 사이트 모두 브라우저 콘솔 오류 없이 기능 QA 7/7 항목을 통과했습니다.

다만 두 Harness 실행 모두 자동 반영까지 끝나지 않았습니다. 단독 실행은 3/3회차 후에도 실제 브라우저 확인이 없다는 판정을 받아 최대 회차에 도달했습니다. Loop 실행은 단위 테스트 8개를 통과했지만, 브라우저 검증이 Chrome 실행을 시도하는 중 Harness 파일 시스템 샌드박스에 차단되어 운영자가 3/3회차에서 중지했습니다. 따라서 이번 결과는 “생성된 웹사이트는 실제 브라우저에서 동작함”을 확인했지만, “두 방식 모두 사람 개입 없이 프로젝트 반영까지 자동 완료함”을 입증하지는 않습니다.

## 비교 조건

- 동일한 요구사항: 외부 의존성 없이 동작하는 반응형 팀 작업 플래너
- 공통 기능: 작업 추가, 담당자 지정, 검색, 전체·진행 중·완료 필터, 완료 전환, 삭제, 브라우저 저장, 손상된 저장 데이터 복구
- 단독 Harness: 계획·구현·판정에 GPT-6 Luna Max 사용
- Loop Harness: 계획·판정에 GPT-6 Luna Max, 구현은 GPT-6 Sol Max부터 시도하고 시간 초과 뒤 저장된 우선순위에 따라 GPT-6 Luna Max로 자동 전환
- 모델별 실행은 각각 1회이며 성공률 통계로 일반화하지 않음
- 비용은 실행별 과금액을 확인할 수 없어 계산하지 않음

### 실행 상태 해석

- 단독 실행의 최종 `npm run verify`는 10개 테스트를 통과했지만, 판정 모델은 실제 브라우저에서의 조작과 새로고침 저장 검증이 빠졌다고 보아 완료 판정을 내리지 않았습니다.
- Loop는 Sol Max 호출이 약 15분 뒤 시간 초과되었고, 설정된 대체 우선순위에 따라 Luna Max로 전환했습니다. 이 대체 전환 자체는 자동으로 동작했습니다.
- Loop의 검증 명령은 단위 테스트 8개를 통과했지만, 브라우저 검증이 설치된 Chrome을 실행할 때 `SIGABRT`로 종료됐습니다. 로그에는 앱 코드 오류가 아니라 Chrome 프레임워크 파일을 Harness 파일 시스템 샌드박스가 읽지 못한 것으로 기록됐습니다.
- 두 모델 산출물을 실제 브라우저에서 별도로 열어 QA했을 때 모든 핵심 상호작용이 통과했습니다. 따라서 자동 판정의 미완료와 실제 앱 기능의 실패를 같은 결과로 취급하면 안 됩니다.

## 실제 브라우저 QA

두 앱에 동일한 작업 세 개를 넣고, 한 건을 완료 상태로 맞춘 뒤 비교했습니다.

1. 사이트가 오류 없이 열리고 기본 화면이 렌더링됨
2. 담당자를 지정해 새 작업 추가
3. 제목 검색으로 작업 찾기
4. 완료 상태 전환과 진행률 갱신
5. 완료 항목 필터 적용
6. 새로고침 후 작업과 완료 상태 유지 확인
7. 시험 작업 삭제

각 사이트 7/7 항목을 통과했습니다. 앱 자체 테스트에서는 빈 저장 공간과 손상된 저장 데이터의 복구도 확인했습니다.

## 디자인 비교

- **단독 Harness:** 한국어 UI, 크림색 배경과 짙은 녹색·코랄 포인트, 가로 진행률 막대와 간결한 작업 목록을 사용합니다. 한국어 사용자가 바로 이해하기 쉽고 화면이 단정합니다.
- **Loop Harness:** 영문 UI와 큰 세리프 제목, 원형 진행률, 담당자 아바타, 작업 상태 구분을 사용합니다. 정보 위계와 편집형 인상이 더 강하고 팀 플래너라는 제품 성격이 잘 드러납니다. 한국어 우선 제품으로 쓰려면 화면 문구 현지화가 필요합니다.

디자인은 점수화하지 않았습니다. 현재 비교에서는 Loop가 시각적 개성이 강하고, 단독 버전은 한국어 접근성과 한눈에 읽히는 간결함이 강점입니다.

## 토큰·시간·사람 개입 분석

- Loop의 기록 토큰은 단독보다 113,007개 적어 **약 17.4% 감소**했습니다.
- Loop 실행 시간은 단독의 **약 2.0배**였습니다. Sol Max 시간 초과와 Luna Max 대체 호출이 포함된 시간입니다.
- 코드 생성 후 사람이 Morrow 앱 소스 코드를 직접 수정한 횟수는 양쪽 모두 0회입니다.
- 반면 실제 브라우저 QA는 Harness 샌드박스 밖에서 별도로 수행해야 했습니다. 자동화된 전체 완료·반영은 양쪽 모두 0/1입니다.
- 정확한 브라우저 QA 공수와 API 달러 비용은 별도로 계측할 수 없었습니다. 토큰 감소를 비용 절감으로 단정하지 않습니다.

따라서 이번 한 번의 실행에서는 Loop가 토큰을 덜 썼지만 더 빠르거나 더 자동으로 완료되지는 않았습니다. 사용자 관점의 최종 앱 기능 QA는 양쪽 모두 통과했으나, 자동 완료 성공률은 단독 0/1, Loop 0/1입니다. 표본이 각각 한 번이라 일반적인 성공률 비교가 아닙니다.

## Loopline 수정과 회귀 검증

이번 재실행 전에 확인된 Loopline 문제를 좁게 수정했습니다.

- Harness 모델 역할 호출 제한 시간을 10분에서 15분으로 늘렸습니다. 일반 대화 제한 시간은 바꾸지 않았습니다.
- 검증 계획과 판정에 테스트 소스 본문을 전달하도록 해, 판정 모델이 실제 테스트를 근거로 검증하게 했습니다.
- 반복해서 같은 파일을 읽는 작업자 모델에 현재 파일 내용과 복구 안내를 한 번 전달하고, 같은 반복이 계속되면 제한된 방식으로 중단하도록 했습니다.
