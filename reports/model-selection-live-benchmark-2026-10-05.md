# GPT-6-Luna Max 단독과 자동 모델 선택 Loop 실측 보고서

## 요약

같은 FocusLog CLI 과제를 GPT-6-Luna Max 단독 Harness와 자동 모델 선택 Loop에 각각 한 번씩 실행했습니다. 두 실행 모두 첫 회차에 자동 완료·반영됐고, 내부 테스트 4개와 같은 조건으로 직접 작성한 독립 블랙박스 검사 9개를 모두 통과했습니다.

이번 단일 표본에서는 Loop가 단독보다 보고 토큰을 **68.1% 적게** 사용했고 Harness 실행 시간이 **32.7% 짧았습니다**. 다만 각 방식의 실행이 한 번뿐이라 일반적인 성공률이나 모델 우위를 확정할 수는 없습니다. Loop 산출물은 정상 동작 검사에는 통과했지만, 저장 도중 프로세스가 끊기는 상황을 위한 원자적 파일 교체는 구현하지 않았습니다.

## 비교 조건

- **과제:** 외부 패키지 없는 Node.js CLI `focuslog.mjs` 제작
- **공통 기능:** 분·메모가 있는 집중 기록 추가, 목록, 합계, ID 삭제, 빈 저장소와 입력 오류 처리, `node --test` 테스트, README 사용 예시
- **단독:** 계획·구현·판정 모두 GPT-6-Luna, Effort `max`, 모델 전환 없음
- **Loop:** 자동 모델 배정과 Jev 판정 사용. 실제 계획은 Gemini 3 Flash Preview, 구현은 GPT-6-Sol `max`, 판정은 Jev latest가 담당했습니다.
- **공통 설정:** 같은 입력 과제, 결과 품질 우선순위, 최대 4회차, 자동 검증·반영, 새 관리 프로젝트 사용, MCP와 Agent Plugin 비활성화
- **완료 정의:** 프로젝트 검증 통과, 최종 판정 통과, 자동 반영 완료
- **환경:** Loopline macOS 로컬 앱, Node.js 26.8.0
- **범위:** 비교 실행은 방식별 1회. 모델 API가 보고한 토큰과 Harness 기록 시간을 사용했습니다. 누락 토큰은 없었습니다.

실행 과제는 두 방식에 동일하게 전달했습니다.

> 의존성 없는 Node.js CLI focuslog.mjs를 만들어 주세요. add <분> <메모>, list, total, delete <id>를 JSON 파일에 저장해 지원하고 빈 저장소와 입력 오류를 안전하게 처리하세요. node --test 자동 테스트와 README 사용 예시를 포함해 실제 검증하세요.

## QA 결과

두 프로젝트에서 각각 모델이 만든 테스트를 실행했습니다.

- 단독: `node --test` — **4/4 통과**, 종료 코드 0
- Loop: `node --test focuslog.test.mjs` — **4/4 통과**, 종료 코드 0

같은 외부 블랙박스 검사를 두 프로젝트에 각각 새 임시 작업 폴더를 만들어 실행했습니다. 과제에 맞춰 현재 작업 폴더의 JSON 저장 파일을 대상으로 검사했습니다.

1. 빈 저장소의 목록 표시
2. 여러 단어 메모 추가와 저장 내용 확인
3. 두 기록 목록 표시
4. 전체 시간 합계
5. 0분 입력 거부와 기존 데이터 보존
6. 존재하지 않는 ID 삭제 거부와 기존 데이터 보존
7. 한 기록 삭제 후 나머지 기록 보존
8. 손상된 JSON을 추가 작업으로 덮어쓰지 않는지 확인
9. 종료 후 저장 파일에 같은 결과가 남는지 확인

결과는 단독 **9/9 PASS**, Loop **9/9 PASS**였습니다. 두 실행 모두 새 프로젝트 폴더에 자동 반영됐습니다. 명령줄 프로그램이라 브라우저 QA는 적용 대상이 아닙니다.

초기 독립 QA 스크립트 초안은 GPT 단독 산출물에만 구현된 선택 환경변수 `FOCUSLOG_FILE`까지 Loop 산출물에 요구했습니다. 그 조건은 공통 과제에 없어서 QA 조건을 공통 과제에 맞춘 뒤 양쪽 모두 전체 9개를 다시 실행했고 통과했습니다. 이 초안 실패는 제품 결함으로 집계하지 않았습니다.

## 품질 검토와 제한 사항

- 두 프로젝트는 이번 기능 계약과 공통 블랙박스 검사를 모두 통과했습니다. 이번 결과에서는 기능 완료와 테스트 통과율이 동률입니다.
- 저장 안정성 구현에는 차이가 있습니다. 단독 산출물은 임시 파일에 쓴 다음 저장 파일을 교체합니다. Loop 산출물은 기존 `logs.json`에 직접 씁니다. 따라서 Loop 결과는 프로세스가 저장 도중 종료되는 상황에서 기존 파일을 보존한다고 보장할 수 없습니다. 이번 독립 검사는 손상된 파일을 덮어쓰지 않는 동작을 확인했지만, 쓰기 중 강제 종료는 모의하지 않았습니다.
- 실행 중 사용자 재개·중지 횟수는 둘 다 0회입니다. 실제 작업자 투입 시간은 계측하지 않았으며, 독립 QA는 실행 완료 후 별도로 자동 수행했습니다.
- 달러 비용은 기록하지 않았습니다. 연결별 실제 과금액을 실행 단위로 확인할 수 없어 토큰을 가격으로 환산하지 않았습니다.
- 각 방식은 한 번만 실행했습니다. 1/1 완료는 관찰값이지 신뢰 가능한 일반 성공률이 아닙니다. 모델·Effort별 추천을 확정하려면 동일 과제 유형에서 반복 실행하고 독립 과제도 추가해야 합니다.
- Loop의 절감은 이 과제에서 관찰된 값입니다. 다른 프로젝트의 완료 품질이나 사용량도 같은 비율로 좋아진다고 볼 수 없습니다.

## 결론

이번 FocusLog 과제에서는 Loop가 GPT-6-Luna Max 단독과 같은 완료·테스트 결과를 내면서 토큰과 실행 시간을 줄였습니다. 자동 배정 과정에서 계획·구현·판정에 각기 다른 연결이 실제 호출된 것도 확인했습니다. 따라서 이번 과제에서는 Loop가 효율 면에서 더 나은 결과였습니다.

다음 비교에서는 동일한 조건으로 최소 3회 이상 반복해 완료 성공률과 토큰·시간의 변동 폭을 확인하고, Loop 저장 파일의 원자적 기록 여부도 별도 복구 검사로 평가할 필요가 있습니다.
