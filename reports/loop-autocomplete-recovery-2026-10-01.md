## 복구 범위와 반영 조건

- 형식 보완은 동일 단계에서 한 번으로 제한합니다. 검증 명령 판정은 기존의 보완 횟수를 사용해 중복 재시도가 생기지 않도록 했습니다.
- 구현 일시 오류의 추가 재시도는 회차당 한 번입니다. 계속 실패하면 기존 회차 한도와 정체 감지 안에서 이어가며, 검증되지 않은 변경을 반영하지 않습니다.
- 자동 회차는 기존 설정에 따라 최대 10회까지 이어집니다. 고정 회차를 선택한 실행은 사용자가 정한 한도를 지킵니다.
- 사용자의 중지 요청, 인증 오류, 소진된 한도에는 같은 모델을 자동 반복하지 않습니다.
- MCP 실행 후 오류가 발생했거나 앞선 MCP 작업의 부작용 가능성이 남아 있으면 구현 재시도·미완료 회차 반복을 차단합니다. 도구를 사용하지 않는 판정 전용 Jev의 형식 보완은 허용합니다.
- 검증 실패, 유효한 완료 판정 없음, 원본 변경 충돌 등의 반영 차단 조건은 유지합니다.

## 적용과 확인 한계

구현과 테스트를 별도 커밋으로 기록하고 데스크톱 패키지를 갱신했습니다. 정상 종료 후 새 패키지로 앱을 다시 열었으며, 패키지에 포함된 `harness-engine.mjs`와 `api-connections.mjs`의 SHA-256이 저장소 소스와 각각 일치하는 것을 확인했습니다. 기존 계정 연결과 자동 회차 설정도 화면에서 확인했습니다.

실제 GPT 제작은 공통 구현 복구 경로를 수정한 뒤 시작했습니다. Jev 오류 분류·native 보완 사유 전달은 제작 시작 이후 추가했으며, 최종 전체 회귀 검사로 따로 검증했습니다. 실제 제작용 격리 서버는 Codex CLI 0.159.0을 사용했고, 주 데스크톱 앱의 기존 CLI 경로 설정은 유지했습니다.

이번 실제 제작은 작은 CLI 과제 한 건입니다. 웹사이트와 같은 큰 작업의 성공률·디자인 품질·토큰 효율 개선을 증명하는 실험은 아닙니다. 웹 UI 판정은 현재 변경 내용의 근거를 사용하므로, 실제 렌더링 품질에는 별도 브라우저 QA가 필요합니다. 일시 장애가 장기간 지속되거나 모든 모델의 한도가 소진되면 완료를 보장할 수 없습니다.
