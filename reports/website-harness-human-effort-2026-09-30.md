# 웹사이트 제작: 단독 Harness와 Loop Harness 비교 QA

## 요약

동일한 요구사항으로 한국어 작업 관리 대시보드(Fieldnote)를 각각 GPT-6 Luna Max 단독 Harness와 Loop Harness로 제작하고, 자동 반영 여부와 기능 검증 결과를 비교했다.

두 방식 모두 최종 산출물은 작업 추가·검색·상태 필터·완료 처리·삭제·브라우저 저장·손상 데이터 복구를 구현했고, 공통 독립 QA 10개 항목을 모두 통과했다. 이번에 완료된 실행만 보면 둘 다 1회 중 1회 성공했지만, Loop는 첫 실행에서 모델 시간 초과를 대체 모델로 넘기지 못해 실패했다. 해당 오류를 수정하고 다시 실행한 뒤에는 대체 모델 전환, 판정, 검증, 자동 반영까지 완료했다.

성공률 표본은 방식별 1회뿐이므로 일반적인 성공 확률로 해석할 수 없다. 확인 가능한 인간의 웹사이트 코드 수정은 양쪽 모두 0회다. 단, Loop의 첫 실패를 복구하려고 Harness 자체를 수정하고 다시 실행한 엔지니어링 개입 1회가 있었다. 그 개입 시간은 따로 측정하지 않았다.

## 비교 조건

- 동일 요구사항: 외부 의존성 없이 동작하는 반응형 웹 작업 관리 대시보드
- 필수 기능: 작업 추가, 제목 검색, 전체·진행 중·완료 필터, 완료 전환, 삭제, 브라우저 저장, 손상된 저장 데이터 복구
- 단독 Harness: 계획·구현·판정 모두 GPT-6 Luna Max, 대체 모델 없음
- Loop Harness 최종 재실행: 계획·판정 GPT-6 Luna Max, 구현 GPT-6 Sol Max, 시간 초과 시 저장된 다음 우선순위 모델인 GPT-6 Luna Max로 전환
- 두 완료 산출물에 동일한 독립 공통 QA 10개를 적용
- 시간은 Harness 실행에 표시된 경과 시간이다. 사람의 수정·재실행 준비 시간은 포함되지 않았다.

## Loop의 첫 실패와 수정

첫 Loop 실행은 Gemini Flash 계획 모델과 Jev 판정 호출을 실제로 수행했지만, GPT-6 Sol Max 구현 호출이 10분 37초 후 시간 초과됐다. 앱이 한국어 시간 초과 메시지를 재시도 가능한 오류로 분류하지 않아 저장된 대체 모델로 넘어가지 못했다. 첫 시도는 완료되지 않았다.

실패를 재현한 뒤 Harness의 오류 분류를 수정하고 회귀 테스트를 추가했다. 수정 후 Loop를 다시 실행하자 Sol Max 시간 초과 뒤 저장 순서에 따라 Luna Max로 자동 전환했고, 잘못 제시된 검증 명령도 판정 단계에서 수정한 다음 검증과 자동 반영까지 마쳤다. 첫 시도의 계획·판정에서 Gemini와 Jev 호출 자체는 확인했다. 다만 키가 기존 앱의 메모리에만 남아 있어 최종 재실행은 키를 옮기지 않은 격리 Codex-only 환경에서 수행했다. 따라서 최종 Loop 수치는 Gemini·Jev 조합이 아니라 Luna·Sol 조합이다.

## 사람의 개입과 성공률 해석

- **단독 Harness:** 웹사이트 제작을 위한 사람의 코드 수정이나 재시도는 관찰되지 않았다. 완료 실행 1회가 자동 판정·검증을 통과했다.
- **Loop Harness:** 수정 완료 후 실행에서는 웹사이트 코드를 사람이 고치지 않았다. 하지만 제품의 대체 모델 처리 오류 때문에 첫 실행이 실패했고, Harness 수정과 재실행이 필요했다. 이 제품 복구 작업은 사이트 코드 작업과 구분해야 한다.
- **완료된 최종 실행 기준:** 단독 1/1, 수정된 Loop 1/1.
- **Loop 수정 전 최초 시도 포함:** 최초 시도 0/1 성공, 수정 후 재실행 포함 전체 1/2 성공. 이는 한 번의 복구 사례이지 장기 성공률 통계가 아니다.

따라서 이번 샘플은 두 방식이 모두 웹사이트를 완성할 수 있음을 보여주지만, 수정 전 Loop가 단독보다 성공률이 높다고 입증하지 않는다. 이번에 확인된 Loop의 실질적인 이점은 여러 모델을 연결하고, 수정된 오류 복구 경로에서 저장된 우선순위대로 대체 모델을 사용해 검증까지 자동 완료한 점이다. 그 대가로 최종 실행 시간이 단독보다 약 2.39배 길었다.

## 토큰·비용 해석

최종 Loop 실행 기록에는 370,286토큰이 집계됐지만, 시간 초과된 Sol Max 호출은 사용량이 반환되지 않았다. 따라서 이 값은 **최소 기록량**이다. 단독 실행 413,068과 단순 비교하면 화면상 기록량은 약 10.4% 적어 보이지만, 누락된 사용량 때문에 Loop가 실제로 토큰을 절약했다고 결론 내릴 수 없다.

첫 실패 실행의 기록 사용량 28,794토큰(Gemini Flash 27,919 + Jev 875)을 최종 Loop 기록량에 더해도 총량의 하한은 399,080토큰이며, 시간 초과 호출 사용량과 사람의 복구 시간은 포함하지 않는다. 제공자별 실행 금액을 신뢰할 수 있게 확인할 수 없어 달러 비용은 산출하지 않았다.
